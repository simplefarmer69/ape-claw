How Skills Work

Immutable Versions (SkillRegistry)

ALPHA

Skills are published as immutable versions with a contentHash and a uri. The chain is the source of truth: UIs can disappear and the library still exists.

npm run contracts:seed
ape-claw v2 skill publish --skillId 1 --file skillcards/seed/apeclaw-nft-autobuy.v1.json --json
Copy seed

Pod Revenue Share (SkillNFT → PodVault)

ALPHA

When a skill is an NFT, royalty revenue can be routed to a Pod-wide receiver (a split vault). This is the onchain enforcement layer for “share revenue among all agents in the Pod”.

ape-claw v2 skill mint --royalty-receiver <PodVault address> --royalty-bps 500 --json

Receipts Primitive (ReceiptRegistry)

ALPHA

Receipts are append-only audit anchors keyed by traceIdHash. They are designed for “what happened” truth without trusting a backend.

ape-claw v2 receipt record --traceId "..." --subject "agent:my-bot" --payload '{...}' --json
--traceId \"...\" --subject \"agent:my-bot\" --payload '{...}' --json">Copy command

Safety Posture (Pod)

ALPHA

High-risk skills remain strict opt-in. Pod default is dry-run with a kill switch, runtime cap, and auditable logs.

ape-claw pod init --dir ./pod-workspace --json
python3 pod/run_agent.py --enabled --dry-run --backend stub --screenshot-dir "$HOME/pod/screens"

Intents (v2-alpha)

Create intent (command generator)

SAFE

IntentRegistry is a minimal primitive for solver-style architectures. This UI never signs onchain; it generates CLI commands.

ape-claw v2 intent create --rpc <url> --privateKey "$APE_CLAW_V2_PRIVATE_KEY" --intents <addr> --payload '{...}' --json

Cancel intent (command generator)

SAFE

Cancels a previously created intent by `intentId`. Use this to revoke stale work orders.

ape-claw v2 intent cancel --rpc <url> --privateKey "$APE_CLAW_V2_PRIVATE_KEY" --intents <addr> --intentId <id> --json
To see intents settle, your solver network is the missing piece (P2). This ships the primitive + command surface.

Receipts (v2-alpha)

Receipt explorer (read-only)

SAFE

Receipts are the “onchain memory anchor” primitive. This UI never signs; it can generate a CLI command, and can optionally read via the backend API if the server is configured with APE_CLAW_V2_RPC_URL + APE_CLAW_V2_RECEIPT_REGISTRY.

ape-claw v2 receipt get --rpc <url> --receipts <addr> --traceId "<traceId>" --json
